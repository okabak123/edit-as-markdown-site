Architecture

  • Edit as Markdown for Jira is an Atlassian Forge app that qualifies for Runs on Atlassian. Atlassian's eligibility check passes for the production version.
  • The app is a Custom UI only. Its code runs in the user's browser inside a sandboxed frame served by Atlassian.
  • No backend: we operate no servers, and the app has no Forge functions or remote services.
  • No egress: the app declares no external network permissions. It talks only to the Jira site it is installed on, through Atlassian's own APIs.
  • No storage: the app uses no Forge storage and keeps no copy of your content. It writes no logs and runs no analytics.
  • No Atlassian credentials, API tokens or passwords are used or stored. Every request is made as the signed-in user, through Atlassian's Forge bridge.

Permissions (scopes)

  • read:jira-work: read the issue description and comments, the issue's edit metadata and your own permissions for the issue.
  • write:jira-work: save the description or comment you edited, only when you press Save.
  • read:jira-user: identify the current user, so only comments you may edit are offered as editable.
  • Jira enforces its normal permissions on every read and write. The app adds a read-only mode when you can't edit, and never widens access.

Content safety

  • The preview renders Markdown with raw HTML disabled, and all dynamic text is escaped.
  • The page has no inline scripts and no relaxed content security policy.
  • Before saving, the app verifies that unchanged content converts back exactly. It shows a diff of every change and asks before removing protected items.
  • If someone else changed the content in the meantime, the app refuses to overwrite it.

Dependencies

  • Runtime dependencies are audited before each release (npm audit, 0 known vulnerabilities at the last release). Vulnerable transitive packages are pinned to fixed versions.

Reporting a vulnerability

  • Email security@grotesque.ltd with the steps to reproduce, the affected version (shown in Jira under Apps → Manage apps) and the impact. Please don't include customer data you aren't authorised to share.
  • We acknowledge reports within 1 business day (UK time). Fixes follow Atlassian's Security Bug Fix Policy for cloud apps: critical within 10 days, high within 4 weeks, medium within 12 weeks, low within 25 weeks of triage. See https://developer.atlassian.com/platform/marketplace/security-bugfix-policy/.
  • We will tell you when the issue is fixed and, if you wish, credit you.
  • If customer data could be affected, we notify Atlassian and affected customers through Atlassian's incident process.
